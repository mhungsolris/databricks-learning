Use Apache Iceberg v3 features 
Apache Iceberg v3 enhances query performance and introduces new capabilities for managed tables using Iceberg or Delta Lake with Iceberg reads in Unity Catalog . 
The key features of Iceberg v3 are: 
Deletion vectors : Enable efficient, row-level deletes without rewriting entire data files. See Deletion vectors in Databricks . 
VARIANT data type : Supports storing and processing semi-structured data. See Variant type support for Apache Iceberg and Delta Lake . 
Row lineage : Tracks incremental changes to table data. See Row tracking in Databricks . 
GEOMETRY and GEOGRAPHY data types : Store and query geospatial data for spatial analytics and joins. See GEOMETRY type and GEOGRAPHY type . 
Write defaults : Specify column values that apply to new rows when a write omits a column. See Create a table with write defaults . 
Requirements ​ 
To use managed tables with Iceberg v3 features, such as geospatial types, you must meet the following requirements: 
A workspace with Unity Catalog enabled. 
Databricks Runtime 18 LTS and above. 
Create a new table with Iceberg v3 ​ 
Create new tables with Iceberg v3 enabled for both managed Delta Lake tables with Iceberg reads and managed Iceberg tables. 
Delta Lake 
Iceberg 
To create a new managed table using Delta Lake with Iceberg reads and Iceberg v3 enabled, use the following SQL command: SQL 
CREATE OR REPLACE TABLE main . schema . table ( c1 INT ) TBLPROPERTIES ( 'delta.universalFormat.enabledFormats' = 'iceberg' , 'delta.enableIcebergCompatV3' = 'true' ) ; 
For more information about Iceberg reads, see Read Delta Lake tables with Iceberg clients . 
To create a new managed table using Iceberg v3, use the following SQL command: SQL 
CREATE OR REPLACE TABLE main . schema . table ( c1 INT ) USING iceberg TBLPROPERTIES ( 'format-version' = 3 ) ; 
For more information about Iceberg tables, see What is Apache Iceberg in Databricks ? . 
Upgrade an existing table to Iceberg v3 ​ 
You can upgrade an existing table to Iceberg v3 by: 
Enabling any v3 feature on a table. 
Setting the Iceberg format version on a table to 3 (shown below). info 
Tables can be downgraded from v3 to v2 by restoring the table to a table version before the upgrade to v3 using RESTORE . See Downgrade a table to a previous version . 
Delta Lake 
Iceberg 
To upgrade a managed table using Delta Lake with Iceberg reads to v3, use the following command: SQL 
ALTER TABLE catalog . schema . table SET TBLPROPERTIES ( 'delta.enableIcebergCompatV3' = 'true' , 'delta.enableIcebergCompatV2' = 'false' ) ; 
To upgrade a managed table using Iceberg to v3, use the following command: SQL 
ALTER TABLE catalog . schema . table SET TBLPROPERTIES ( 'format-version' = 3 ) ; 
Enable deletion vectors ​ 
Deletion vectors optimize row-level data modification operations and are enabled by default on all new Iceberg v3 tables. See Deletion vectors in Databricks . note 
Enabling deletion vectors on an existing Iceberg table upgrades the Iceberg format version to 3. 
Delta Lake 
Iceberg 
To create a new managed table using Delta Lake with Iceberg reads, Iceberg v3, and deletion vectors enabled, set the following table properties: SQL 
CREATE TABLE catalog . schema . table ( c1 INT ) TBLPROPERTIES ( 'delta.enableDeletionVectors' = 'true' , 'delta.enableIcebergCompatV3' = 'true' , 'delta.universalFormat.enabledFormats' = 'iceberg' ) ; 
To create a new managed table using Iceberg v3 with deletion vectors enabled, set the iceberg.enableDeletionVectors table property: SQL 
CREATE TABLE catalog . schema . table ( c1 INT ) USING ICEBERG TBLPROPERTIES ( 'iceberg.enableDeletionVectors' = 'true' ) ; 
Use the VARIANT data type ​ 
The VARIANT data type allows you to store and query semi-structured data. note 
Using VARIANT in an existing Iceberg table upgrades the Iceberg format version to 3. 
Delta Lake 
Iceberg 
To create a new managed table using Delta Lake with Iceberg reads and a VARIANT column: SQL 
CREATE TABLE catalog . schema . deltaTable ( col VARIANT ) TBLPROPERTIES ( 'delta.enableIcebergCompatV3' = 'true' , 'delta.universalFormat.enabledFormats' = 'iceberg' ) ; 
To create a new managed table using Iceberg v3 with a VARIANT column: SQL 
CREATE TABLE catalog . schema . icebergTable ( col VARIANT ) USING iceberg ; 
To add a VARIANT column to an existing table, use the ALTER TABLE command: SQL 
ALTER TABLE catalog . schema . table ADD COLUMN variant_col VARIANT ; 
Use GEOMETRY and GEOGRAPHY data types ​ 
Use the GEOMETRY and GEOGRAPHY data types to store and query geospatial data. See GEOMETRY type and GEOGRAPHY type . note 
Using GEOMETRY or GEOGRAPHY in an existing Iceberg table upgrades the Iceberg format version to 3. 
Delta Lake 
Iceberg 
To create a new managed table using Delta Lake with Iceberg reads and GEOMETRY or GEOGRAPHY columns: SQL 
CREATE TABLE catalog . schema . table ( geom_col GEOMETRY ( 3857 ) , geog_col GEOGRAPHY ( 4326 ) ) TBLPROPERTIES ( 'delta.enableIcebergCompatV3' = 'true' , 'delta.universalFormat.enabledFormats' = 'iceberg' ) ; 
To create a new managed table using Iceberg v3 with GEOMETRY or GEOGRAPHY columns: SQL 
CREATE TABLE catalog . schema . table ( geom_col GEOMETRY ( 3857 ) , geog_col GEOGRAPHY ( 4326 ) ) USING iceberg ; 
To add a GEOMETRY or GEOGRAPHY column to an existing table, use the ALTER TABLE command: SQL 
ALTER TABLE catalog . schema . table ADD COLUMN geom_col GEOMETRY ( 3857 ) ; ALTER TABLE catalog . schema . table ADD COLUMN geog_col GEOGRAPHY ( 4326 ) ; 
Create a table with write defaults ​ 
Iceberg v3 defines two types of default values: 
Write defaults apply to new rows when a write omits the corresponding column. Databricks supports write defaults. 
Initial defaults apply to preexisting rows when a new column is added. Databricks doesn't support initial defaults. 
Delta Lake 
Iceberg 
To create a new managed table using Delta Lake with Iceberg reads and a write default: SQL 
CREATE TABLE catalog . schema . table ( id INT , row_status STRING DEFAULT 'active' ) TBLPROPERTIES ( 'delta.enableIcebergCompatV3' = 'true' , 'delta.universalFormat.enabledFormats' = 'iceberg' ) ; 
To create a new managed table using Iceberg v3 with a write default: SQL 
CREATE TABLE catalog . schema . table ( id INT , row_status STRING DEFAULT 'active' ) USING iceberg ; 
To see the default applied, insert a row without row_status : SQL 
INSERT INTO catalog . schema . table ( id ) VALUES ( 1 ) ; SELECT * FROM catalog . schema . table ; 
The preceding query returns the following, with the default applied to row_status : Output 
id  row_status 1   active 
Downgrade a table to a previous Apache Iceberg version ​ 
If you need to revert a table to a state before it was upgraded to Iceberg v3, you can use the RESTORE command. SQL 
set spark . databricks . delta . restore . protocolDowngradeAllowed = true ; RESTORE TABLE catalog . schema . table TO VERSION AS OF 1 ; set spark . databricks . delta . restore . protocolDowngradeAllowed = false ; 
Limitations ​ 
Databricks supports version 3 of the Iceberg specification, with the following exceptions: 
Initial defaults aren't supported. When a new column is added, an initial default sets the value for preexisting rows. 
The following data types aren't supported: 
Unknown type 
Nanosecond precision timestamp. 
Multi-argument transforms aren't supported. On this page
